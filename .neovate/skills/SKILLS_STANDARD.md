# Skill 标准格式定义

本文档定义了 Power Skills 仓库中每个 Skill 必须遵循的标准格式。

## Skill 目录结构

每个 Skill 必须是一个独立的目录，目录结构如下：

```
<skill_name>/
├── SKILL.md              # 技能概述文件（必需）
├── <topic1>.md          # 功能文档（可选，多个）
├── <topic2>.md
└── ...
```

## SKILL.md 标准格式

`SKILL.md` 是每个技能的入口文件，必须包含以下章节：

```markdown
# <技能名称>

## 适用范围

此技能集适用于...（描述使用场景和技术范围）

## 何时使用

当项目需要...时使用，包括：
- 特性 1
- 特性 2
- ...

## 文件说明

| 文件 | 说明 |
|------|------|
| file1.md | 文件说明 |
| file2.md | 文件说明 |
| ... | ... |

## 技术栈

- 技术项 1: 版本/描述
- 技术项 2: 版本/描述
- ...
```

### 必需字段

- `# 标题` - 技能名称
- `## 适用范围` - 描述技能适用的技术范围
- `## 何时使用` - 列出触发使用该技能的场景
- `## 文件说明` - 表格形式列出所有子文档及说明
- `## 技术栈` - 列出关键技术和版本

### 可选字段

- `## 架构原则` - 该技能遵循的核心架构原则
- `## 命名约定` - 统一的命名规范

## 子文档格式规范

每个子文档应聚焦单一主题，遵循以下规范：

### 文档标题

```markdown
# <主题名称>
```

### 内容结构

建议按以下顺序组织内容：

1. **概述** - 简要说明该主题的作用
2. **代码模板** - 提供可复用的代码模板
3. **命名约定** - 统一的命名规范（如文件名、变量名、函数名等）
4. **最佳实践** - 推荐的做法和注意事项
5. **示例** - 完整的使用示例

### 代码块格式

所有代码块必须指定语言：

```rust
// Rust 代码
use std::sync::Arc;

pub fn example() {
    // ...
}
```

```typescript
// TypeScript 代码
interface Example {
    name: string;
    value: number;
}
```

```bash
# Shell 命令
npm install package-name
```

## 命名约定

### 目录名

- 使用 `snake_case` 格式
- 描述技术栈或框架名称
- 示例：`axum_backend`、`nextjs_frontend`

### 文件名

- 使用 `snake_case.md` 格式
- 聚焦单一主题
- 使用描述性名称
- 示例：`handlers.md`、`data_fetching.md`、`error_handling.md`

### 文档标题

- 使用中文标题
- 简洁明了
- 示例：`# Handlers - 请求处理器`、`# 数据获取`

## 内容质量要求

### 代码模板

- 提供完整可用的代码模板
- 包含必要的导入语句
- 使用实际的类型和变量名
- 添加关键注释说明

### 最佳实践

- 提供具体可行的建议
- 说明为什么这样做
- 列出常见陷阱和注意事项

### 一致性

- 同一技能内的文档保持术语一致
- 命名约定在所有文档中统一
- 代码风格一致

## 文档更新规范

### 版本信息

每个技能文档应在 SKILL.md 中注明版本信息（可选）：

```markdown
## 版本信息

- 创建日期: 2025-01-14
- 最后更新: 2025-01-14
- 版本: 1.0
```

### 变更记录

重大变更应在文档中说明：

```markdown
## 变更记录

- 1.0 (2025-01-14): 初始版本
```

## 验证清单

创建或修改 Skill 时，检查以下内容：

- [ ] 目录名使用 `snake_case`
- [ ] 包含 `SKILL.md` 文件
- [ ] SKILL.md 包含所有必需章节
- [ ] 文件说明表格完整
- [ ] 代码块指定了正确的语言
- [ ] 命名约定在文档中统一
- [ ] 提供了完整的代码模板
- [ ] 代码模板包含必要的导入
- [ ] 包含最佳实践说明
- [ ] 使用中文描述
